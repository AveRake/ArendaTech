# АрендаТех — сервис аренды техники для учебных учреждений

Программный комплекс автоматизирует выдачу во временное пользование технических
средств (ноутбуков, проекторов, фото- и видеотехники) студентам и преподавателям:
создание заявок, согласование, выдачу, возврат, расчёт стоимости аренды, начисление
штрафов, уведомления и отчётность.

Проект развивается от лабораторной к лабораторной:

| Версия | Лабораторная работа | Что сделано |
|---|---|---|
| v1.0 | №1–2 (ТЗ, Git, Doxygen) | Требования по ГОСТ 19.201-78, модель прецедентов и классов, классы предметной области, Doxygen-документация |
| v2.0 | №3 (метрики кода) | Новый функционал (расчёт стоимости, штрафы, статусы, JSON-хранилище, CLI, 56 тестов) и рефакторинг по метрикам: 6 нарушений порогов → 0 |

Текущее состояние — **v2.0**: все модули в «зелёной» зоне индекса сопровождаемости,
0 нарушений правил CA1501/CA1502/CA1505/CA1506.

## Быстрый старт

Требуется Python 3.10 или новее.

```bash
# 1. Перейти в каталог проекта
cd ArendaTech

# 2. (необязательно) создать виртуальное окружение
python -m venv .venv
# Windows:  .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate

# 3. Установить зависимости (нужен только pytest; метрики работают без зависимостей)
pip install -r requirements.txt

# 4. Запустить демонстрационный сценарий
python -m src.main
```

Вывод демонстрационного сценария проходит полный цикл: создание заявки → согласование →
выдача → отказ в бронировании занятой единицы → возврат с просрочкой и повреждением →
отчёт → уведомления.

### Команды интерфейса командной строки

```bash
python -m src.main demo                          # демонстрационный сценарий
python -m src.main demo --state data/state.json  # сценарий + сохранение состояния
python -m src.main report --state data/state.json  # отчёт по сохранённому состоянию
python -m src.main metrics                       # метрики кода текущей версии
python -m src.main --help                        # справка
```

Точка входа без аргументов (`python -m src.main`) запускает демонстрационный сценарий.

### Тесты

```bash
python -m pytest -q            # весь набор (56 тестов)
python -m pytest tests/test_service.py -v   # один модуль тестов
```

## Как это работает

### Жизненный цикл заявки

```
На рассмотрении ──approve──▶ Одобрена ──issue──▶ Выдана ──return──▶ Закрыта
        │
        └──reject──▶ Отклонена
```

Переходы проверяются правилом `ALLOWED_TRANSITIONS` в `src/domain/request.py`;
недопустимый переход выбрасывает `InvalidTransition`.

### Расчёт стоимости

`src/pricing.py` применяет набор независимых правил скидок (роль, длительность,
объём заказа). Итог = базовая стоимость × произведение множителей (1 − скидка):

| Правило | Условие | Скидка |
|---|---|---|
| `RoleDiscount` | студент / преподаватель | 10 % / 5 % |
| `LongRentalDiscount` | более 7 / более 14 суток | 5 % / 10 % |
| `BulkDiscount` | 3 единицы и более | 3 % |

Пример: студент, 2 ноутбука по 500 ₽, 10 суток → 10 000 ₽ × 0,9 × 0,95 = **8 550 ₽**.

Чтобы добавить новую скидку, достаточно описать класс с методами `name` и
`discount` и передать его в `PriceCalculator(rules=[...])` — существующий код
менять не нужно.

### Штрафы

`src/fines.py` — правила `OverdueRule` (50 % суточной ставки за каждые сутки
просрочки), `DamageRule` (доля суточной ставки, коэффициент задаётся категорией
техники) и `LossRule` (стоимость возмещения модели). Коэффициенты хранятся в
данных (`Category.damage_coefficient`, `EquipmentModel.replacement_cost`), а не
в коде правил.

### Хранение состояния

`RentalService.state()` возвращает снимок `ServiceState`, который
`src/repository.py` сохраняет через `JsonRepository`. Загрузка восстанавливает
ссылки (выдача → заявка, заявка → единицы техники) и проверяется тестами
`tests/test_repository.py`.

## Метрики кода (лабораторная работа №3)

`metrics/code_metrics.py` вычисляет шесть метрик, аналогичных метрикам Visual
Studio, плюс метрики Холстеда и строки комментариев:

- индекс удобства обслуживания (Maintainability Index, MI);
- цикломатическая сложность (Cyclomatic Complexity, CC);
- глубина наследования (Depth of Inheritance, DIT);
- связность классов (Class Coupling);
- строки исходного кода (Source Lines) и строки исполняемого кода (Executable Lines).

Пороговые правила CA1501, CA1502, CA1505, CA1506 настраиваются в
`metrics/CodeMetricsConfig.txt` в формате, совпадающем с `CodeMetricsConfig.txt`
для Visual Studio.

```bash
# метрики текущей версии (XML + CSV + Markdown + JSON в metrics/reports/current)
python metrics/code_metrics.py src --root . --out-dir metrics/reports/current --label code-metrics

# строгая проверка: код возврата 1, если есть нарушения порогов (удобно для CI)
python metrics/code_metrics.py src --root . --fail-on-violation

# сравнение версий и диаграммы
python metrics/compare_metrics.py \
    metrics/reports/v1.0/code-metrics-v1.0.json \
    metrics/reports/v2.0-raw/code-metrics-v2.0-raw.json \
    metrics/reports/v2.0/code-metrics-v2.0.json \
    --labels "v1.0 (ЛР2)" "v2.0 черновик" "v2.0 итог" \
    --out-dir metrics/reports/comparison --label comparison
```

Форматы отчётов:

| Файл | Назначение |
|---|---|
| `*.xml` | структура `CodeMetricsReport` (как у `Metrics.exe`), плюс блок `RuleViolations` |
| `*.csv` | построчная таблица по модулям, классам и методам (удобно для Excel) |
| `*.md` | готовая сводка для отчёта по лабораторной работе |
| `*.json` | полное дерево метрик для `compare_metrics.py` |

## Правила разработки

- Новая бизнес-логика — в отдельный сценарий (`requests.py`, `issues.py`) или
  правило (`pricing.py`, `fines.py`), а не в `RentalService`.
- `RentalService` — только делегирование; фасад не должен обрастать условиями.
- Порог CC для метода — 10, порог MI для модуля — 20; перед коммитом полезно
  запускать `python metrics/code_metrics.py src --root . --fail-on-violation`.
- Каждая новая функция сопровождается Doxygen-комментарием и тестом.

## Возможные проблемы

| Симптом | Решение |
|---|---|
| `ModuleNotFoundError: No module named 'src'` | запускайте команды из каталога `ArendaTech` (там, где лежит `src/`) |
| `No module named pytest` | `pip install -r requirements.txt` |
| `UnicodeDecodeError: 'charmap' codec can't decode byte ...` при `pip install -r requirements.txt` | `requirements.txt` содержит только латинские символы, поэтому на актуальном pip ошибки нет; если pip старый (21.x) — обновите: `python -m pip install --upgrade pip` |
| В консоли Windows вместо кириллицы «кракозябры» | `set PYTHONIOENCODING=utf-8` или `chcp 65001` |
| `doxygen: command not found` | установите Doxygen и Graphviz, перезапустите терминал |
| Диаграммы сравнения не строятся | установите Pillow: `pip install pillow` |
